Same app.
Three ways to ask.

One scoreboard, built three times by AI. Then one button that nobody understands.

Open with the question: if you ask an AI to build something, what decides whether it works? Today the same small app gets built three times by the same AI model, and only one thing changes between each run. In the second half we use an AI agent to explain and debug code we did not write. Keys: Right or Space for the next step, Left to go back, N for these notes, F for full screen. After clicking inside a live page, move the mouse off it before using the keys. Every live page has two orange buttons: Open shows the page full size in a new browser tab, and the round one reloads it. “All pages” at the bottom right opens demo.html.

THE EXPERIMENT

Three runs, one change at a time

RUN 1

One-line prompt

A powerful AI model and one quick sentence.

RUN 2

Better prompt

The same model with a clear request. One try.

RUN 3

Better harness

The same model and request, plus a rules file that lives in the project.

Same model every time. Each run was made three times, and every page was tested the same way: 8 checks for the app we wanted, 6 checks from the school’s own rules.

Click once per run. Stress that only one thing changes each time, like a science experiment, and that the model never changes: it is Claude Fable 5.2 in Claude Code in all three runs. So whatever gets better today, it is not because the AI got smarter. “Harness” means everything around the model: the rules it reads and the tools it can use.

1

What I did

2

What I expected

The saved count still shows 5.

3

What I saw

The saved count shows 0.

That is all we told the agent. No hint about the cause.

We broke the page on purpose, three times, by changing one line each time. One click per part. This is the run 2 habit again, for a bug instead of an app: say exactly what happened. Compare with “it’s broken, fix it”. The next slide has the broken and the fixed pages side by side.

Four habits that changed the result

1

Say what you want

What it does, the rules, and one example.

2

Say what went wrong

What I did, what I expected, what I saw.

3

Keep the rules in the project

Then nobody has to remember them.

4

Check its work

Tests, and your own eyes.

One click per habit. Habit 1 is the jump from run 1 to run 2. Habit 2 is the bug reports for the mystery button. Habit 3 is the jump from run 2 to run 3. Habit 4 is the tests run 3 wrote and the claims we checked ourselves. The model was the same in all three runs. Nothing here needed a smarter AI. The four habits are yours.
